## Что мы строим

Мобильное приложение — личная медкарта + переводчик анализов на простой язык + напоминалка. Пользователь фотографирует бумажный анализ (кровь/моча/биохимия), приложение распознаёт показатели, объясняет их простым языком, хранит историю и строит графики динамики во времени.

Рабочее название: **HealthVault**.

## ПОЗИЦИОНИРОВАНИЕ И ПРАВИЛА БЕЗОПАСНОСТИ (не подлежат нарушению)

Это несущая стена продукта, а не формальность. Нарушение этих правил делает приложение опасным и подводит его под регуляцию медизделий.

1. Приложение — это информация и хранилище (personal health record), а НЕ диагноз и НЕ замена врачу. Нигде в UI, текстах и ответах модели нельзя формулировать диагнозы.
2. Приложение никогда не успокаивает и не отговаривает от визита к врачу. Если данные тревожные — оно спокойно, но твёрдо направляет к врачу.
3. Никаких предписаний: не назначать лечение, не назначать лекарства, не давать директивных диет («съешьте X, чтобы вылечить Y»). В MVP нутрициологии нет вообще.
4. При паттернах «красных флагов» показывается заметный экран «Обратитесь к врачу».
5. Дисклеймер виден на ключевых экранах: «Это информация, не диагноз и не замена консультации врача».
6. Медданные — особо чувствительная категория. Каждый пользователь видит только свои данные (Row Level Security). Ключи внешних API — только на сервере, никогда в клиенте.
7. Язык интерфейса и объяснений — русский. Объяснения — простым языком, без пугающего жаргона и без нагнетания.

## Стек (зафиксирован)

* Клиент: React Native + Expo, TypeScript. Навигация: expo-router.
* Бэкенд: Supabase — Postgres + Auth + Storage + Edge Functions (Deno).
* Распознавание: Gemini Flash (мультимодальная), вызывается ТОЛЬКО из Edge Function. Ключ — в секретах Supabase.
* Пуши: Expo Notifications.
* Графики: любая лёгкая RN-библиотека графиков (напр. react-native-gifted-charts или victory-native).

Архитектура: тонкий клиент, вся логика распознавания и правила — на сервере. Это позволит позже добавить текстовые заключения (УЗИ/МРТ) без смены стека.

## MVP: что входит и что НЕ входит

Входит:

* Авторизация (email + OTP).
* Съёмка анализа камерой с автокропом + загрузка в Storage.
* Извлечение показателей одним вызовом Gemini Flash → структурированный JSON + объяснения.
* История документов и графики динамики по каждому показателю.
* Детекция красных флагов и экран «к врачу».
* Напоминания (пересдать анализ / лекарства / приём) + пуши.
* Дисклеймеры.

НЕ входит (второй этап, не делай сейчас):

* Текстовые заключения (УЗИ/МРТ/выписки).
* Нутрициология и рекомендации по питанию.
* Психология / wellbeing.
* Мультиязычность.

## Модель данных (Postgres)

Все пользовательские таблицы содержат `user_id uuid` и защищены RLS (`user_id = auth.uid()`).

* **profiles**: `id` (=auth.users.id), `display_name`, `locale` (default 'ru'), `created_at`.
* **documents**: `id`, `user_id`, `storage_path`, `doc_type` enum (`'lab_numeric'` — пока единственное значение), `taken_at` date, `uploaded_at`, `status` enum (`'pending' | 'processed' | 'failed'`).
* **lab_results**: `id`, `document_id`, `user_id`, `analyte_name`, `analyte_code` (nullable), `value` numeric (nullable), `value_text` (nullable, если значение не число, напр. «отрицательно»), `unit`, `ref_low` numeric (nullable), `ref_high` numeric (nullable), `flag` enum (`'normal'|'low'|'high'|'critical_low'|'critical_high'|'unknown'`), `explanation` text, `measured_at` date.
* **red_flags**: `id`, `user_id`, `document_id`, `severity` enum (`'warn'|'urgent'`), `message`, `acknowledged` bool default false, `created_at`.
* **reminders**: `id`, `user_id`, `kind` enum (`'retest'|'medication'|'appointment'`), `title`, `notes` (nullable), `due_at`, `repeat_rule` (nullable), `notification_id` (nullable), `done` bool default false.

(Эти таблицы будут созданы в Промпте №2. Сейчас — только зафиксирована модель.)

## Контракт извлечения (JSON, который вернёт Gemini Flash)

Строгий JSON, никаких пояснений вокруг, никакого markdown:

```json
{
  "doc_type": "lab_numeric | unknown",
  "taken_at": "YYYY-MM-DD | null",
  "lab_name": "строка | null",
  "results": [
    {
      "analyte_name": "нормализованное название показателя",
      "value": 0.0,
      "value_text": "строка, если значение не число, иначе null",
      "unit": "ед. изм. | null",
      "ref_low": 0.0,
      "ref_high": 0.0,
      "flag": "normal|low|high|critical_low|critical_high|unknown",
      "explanation": "1–2 предложения простым языком, БЕЗ диагноза"
    }
  ],
  "overall_note": "общий нейтральный комментарий, без диагноза",
  "red_flags": [
    { "severity": "warn|urgent", "message": "почему стоит показать врачу" }
  ]
}
```

Правила для модели (пойдут в системный промпт функции в Промпте №3): не диагностировать, не успокаивать в обход врача, не назначать лечение/диету; при опасных значениях выставлять `red_flags` с `urgent`; объяснения — простым русским, без нагнетания.

## Соглашения по коду

* TypeScript строгий. Понятные имена. Комментарии только там, где неочевидно.
* Секреты — через переменные окружения / секреты Supabase, никогда в коде клиента.
* Небольшие компоненты, ясная структура папок. README с командами запуска.
